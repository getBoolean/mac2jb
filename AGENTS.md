# Agent workflow

For iPad port hardware work, use the repository skill at `.agents/skills/ipad-port-headless/SKILL.md`. It contains durable procedure, rules, and CLI usage only. The current device state is the **Current state** block at the top of `docs/ipad/target-device-findings.md`; read it and `docs/ipad/usb-recovery.md` before acting on the device. **Never add status updates, trial results, or stop points to the skill.** After a device action, replace the findings Current state block, and record only durable lessons, procedure changes and persistent device changes in the docs (`docs/ipad/README.md` lists them). Do not append dated stop-point logs; history lives in git.

When an investigation stalls after checking the available evidence, ask a **fresh agent** for an independent second opinion before repeating an experiment or concluding that the issue has no solution. Give the agent the current objective, repo paths, observed results, and safety constraints, but no inherited analysis or preferred diagnosis. Ask it to look for missed evidence, test competing explanations, and identify the smallest discriminating next check.

For iPad hardware work, keep the second opinion read-only on the device unless the user has authorized a specific later action. Record its durable findings, corrections, and remaining uncertainty in the iPad findings or recovery documents. Do not treat a second opinion as proof without checking it against source, retained evidence, and a bounded observation.
