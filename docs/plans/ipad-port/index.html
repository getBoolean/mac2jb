Port flight plan

A Mac-free mac2jb workflow on the jailbroken M2 iPad Pro target. The work is ordered around one hard truth: private USB behavior and safe restoration must be proven on the exact device before the runtime, interface, or packaging work earns a release path.

Key problems

These are the problems that determine feasibility or dominate implementation risk. The plan treats them as evidence-producing work, not assumptions.

P–01

USB HID has an implementation path, not a device result

The Mac kext forwards controller configuration rather than implementing HID; on that stack, userspace configures the resulting generic named interface with the class tuple, descriptors, interrupt pipe, and reports. iOS 17 retains the controller/interface family, and TrollStore can preserve the controller entitlement. No public result yet proves arbitrary-function materialization, endpoint operations, or direct Switch role negotiation on this physical iPad14,5 running 17.0.

Plan responseReproduce the generic-interface sequence one operation at a time on the exact ProductType and build, capture generic-host enumeration, restore stock functions, and only then test the Switch. Read the evidence chain and proof protocol.

P–02

A bad descriptor can strand USB

Replacing the active USB description can remove usbmux, networking, or trusted-host functions until reboot—and a crashed worker cannot repair itself.

Plan responseCapture live and default descriptions, externally verify a no-op republish, use additive configuration first, fsync the restore recipe, and give only an independent single-writer watchdog a short mutation lease.

P–03

One port must carry two jobs

The iPad must connect directly to the Switch for HID, but the current exploit workflow assumes a reliable IP path that previously used wired networking.

Plan responseCompare Wi-Fi against a wired baseline over at least 20 attempts, then test only two bounded direct-cable fallbacks.

P–04

TrollStore is not a daemon manager

A TrollStore app can retain private entitlements, but it cannot own the durable launch-daemon lifecycle required for hosts, cleanup, and restoration.

Plan responseSplit the product: a diagnostic/UI .tipa and a Dopamine rootless .deb containing the service, watchdog, helpers, runtimes, and state.

P–05

The desktop runtime does not transplant

Foundation.Process, desktop Node, Python executables, SPIR-V command tools, and app-bundle FFmpeg paths do not map directly to iPadOS.

Plan responseUse posix_spawn, pinned JIT-less Node, embedded Python/Pillow, linked SPIR-V validation, and a bounded iOS media capability.

P–06

Root authority meets untrusted content

The port introduces private entitlements and a root service while processing vendor scripts, imported apps, media URLs, keyboard input, and account data.

Plan responseAuthenticate the installed app by audit token/CDHash plus pairing proof; expose only high-level operations; drop all ordinary work to mobile.

P–07

UI and service failures differ

The interface may disappear without ending a valid host, but a root-service crash can leave unverifiable children, ports, or device state.

Plan responseUI death reconnects from snapshots. Service death fails closed: restore USB, terminate or quarantine unverified trees, and reattach only with existing proof.

P–08

Two artifacts can drift

The app and service update through different channels. A partially installed or incompatible pair must never retain mutation authority.

Plan responseOne signed compatibility manifest, diagnostic-only mixed states, immutable versioned service payloads, atomic activation, and retained rollback.

P–09

Public CI cannot prove the device

Private USB behavior, Dopamine process handling, Switch enumeration, exploit timing, and thermal media limits need the physical target.

Plan responseKeep deterministic CI for builds/contracts, then require signed, redacted, artifact-bound hardware records for release promotion.

Go / no-go gates

A failed gate stops dependent work. It does not silently redefine parity or replace a device requirement with a manual workaround.

USB safety gate — U1 read-only passed; restoration pending

Read-only U1 passes: exact app-build evidence, verified TrollStore installations, installed-code and entitlement attestation, and two validated rounds for each client, platform, and ordinary baseline/set-description profile in Mac A/B and owner-confirmed direct Switch 2 A/B. The interface-client entitlement opened all 16 observed function services with both tested client types; other profiles were denied, and both tested controller opens were unsupported. Pinned Wi-Fi SSH worked with ChatGPT open. Mac A/B each have complete zero-event 90-second USB lifecycle windows for all three profile pairs. The iPad controller reported configured and on-bus with external power on both Switch orientations. Private default/live controller description snapshots matched across two reads; the live configuration list matched the stock source and nine live fields matched the Mac host. The profile remains unchanged with a private backup. U2 no-op restoration, HID publication, and independent Switch 2 enumeration remain untested; the latter is not part of U1's written pass condition.

Network viability gate — not tested

At least 20 comparable attempts per topology. The selected path must remain within 10 percentage points of the wired baseline with no new repeatable transport failure.

Release gate — blocked

Every bundled feature passes, app/service versions agree, Mac regressions stay green, artifacts audit cleanly, and signed target evidence matches the published digests.

Non-negotiable invariants

These constraints survive implementation choices. Any shortcut that breaks one changes the product contract and requires an explicit decision.

No Mac during normal use

After installation, the iPad owns bootstrap entry, hosting, held-session tools, apps, updates, recovery, and diagnostics.

Direct HID remains required

Host-only and manually typed paths may aid development but do not satisfy the parity release.

The UI is not privileged

The app receives only the exact local service lookup entitlement; controller and root authority stay in minimal helpers.

USB has one writer

The watchdog/controller broker alone owns mutation, journal creation, verification, and journal deletion.

Ordinary work runs as mobile

Node, ns2jb, Python, FFmpeg, and homebrew children receive scrubbed groups, environment, and descriptors.

macOS remains supported

Shared seams may change, but the current Mac app, helpers, archive, fixtures, and release audit remain regression targets.

Start with evidence, not the app

The owner removed the older toolbox and platform admission test apps; their validated reports remain historical evidence. Two ordinary SpringBoard R2 apps remain installed and attested, with validated baseline and set-description-only reports in every U1 physical row. The device cleanup ledger tracks current apps, staged archives, report files, SSH entries, and profile backup. U1's read-only decision is recorded as pass. Start U2 by proving its journal, watchdog, and recovery path before any descriptor-changing experiment.
