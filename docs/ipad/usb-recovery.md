## Before a guarded trial

1. Verify the exact device/OS build, boot session, controller identity, and stock-source digest against the journal recipe. Reject a mismatch or an unresolved older journal.

## If the trial fails

**Working same-boot recovery (demonstrated 2026-10-31):** if the controller stays off bus after a swap, read which functions failed to register (`register function` lines in the network syslog that `recover-u2-over-wifi.py` records). Re-publish with `host/recover-u2-until-registered-wifi.py` until only functions with user-space owners are missing, then restart that owner with `host/recover-u2-restart-function-owner-wifi.py com.apple.audiomxd` (Valeria/audio). It brought the controller on bus and the Mac back with a census identical to healthy. Then run the full external check before any confirmation.

**Standard first response (owner policy, 2026-10-31):** run `python3 docs/plans/ipad-port/scripts/ipad-hardware/host/recover-u2-over-wifi.py` once. It backs up the failed journal and all U2 device files into a private kit before anything else, captures the failed-state reference set, issues one broker restore over pinned Wi-Fi SSH with the Mac observer armed, and never confirms. Brokers built from source after 2026-10-31 accept `restore-after-failure` from `awaitingVerification` or `recoveryRequired`, only while the controller reads unconfigured; it bypasses the readiness gate because the first enumeration has already failed (`tests/test-u2-native-wifi-restore.py`). The v8 broker staged on 2026-10-31 (`dev.mac2jb.u2.nooptrialv8`) supports it. Older v4/v7 brokers can only `restore` from `recoveryRequired`; if one of them owns the socket after a reboot, the runner reports `command=none` from `awaitingVerification`. The numbered steps below still apply afterwards.

1. Stop further publication attempts. The watchdog should restore the journaled original description without depending on the canary or the Mac host remaining connected.
2. Recheck pinned Wi-Fi SSH and the watchdog's journal state. Keep a failed or unverified journal and its logs; do not delete or overwrite them to retry.
3. From the Mac, rerun `check-u2-external-current.py` with normal host permissions; require byte-equal raw configurations, equal active interfaces/device scalars and live iPad description, one USBMux/network device, valid pairing, and external power with charging or full battery. Separately prove any active network function recovered. Only the watchdog may mark the journal externally verified and remove it after all required comparisons pass. The current check script prints a category only and does not itself issue a verification proof or clear a journal.
4. If the watchdog cannot restore and Wi-Fi SSH remains usable, stop at `recovery-required` and diagnose the exact failed operation. Do not send an unreviewed registry write or a second description.
5. If headless recovery is unavailable, the owner has previously restored normal access by rebooting and re-jailbreaking the iPad. Treat that as a last-resort physical recovery path; do not initiate it while the owner is away because the jailbreak and SSH may need manual reactivation. It requires a new boot token, exact original live description, all five byte-equal raw Mac configurations, equal active interfaces/scalars, pairing, power, baseline network-driver state, and the unchanged old-boot journal. It was tested to reject the current unchanged boot. A pass is recovery evidence, not permission to delete the journal; preserve it until a separate old-boot cleanup decision is documented.
